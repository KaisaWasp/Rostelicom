# Контекст проекта для нового чата

## Как использовать

Этот файл — актуальная стартовая точка для продолжения работы над проектом **Rostelecom Analytics**. Перед изменениями новый исполнитель должен:

1. Прочитать `AGENTS.md`, этот файл и связанные документы из раздела «Документация».
2. Проверить существующий код перед его изменением.
3. Не запускать `npm run build` без явного разрешения пользователя.
4. Не выдавать демонстрационные данные за реальные и не начинать предметную бизнес-логику без отдельного запроса.

## Назначение продукта

Rostelecom Analytics — внутренняя B2B-аналитическая платформа для поиска коммерческих возможностей и подготовки сделок. Фронтенд реализуется поэтапно.

Три ключевых модуля:

| Модуль                   | Цель                                                                                                                       |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| Радар присутствия        | Найти территории и организации с потенциалом, увидеть клиентский статус и «белые пятна» покрытия.                          |
| Инвестиционный навигатор | Найти инвестиционные проекты, их стадии и потребности в ИТ-инфраструктуре, АСУ ТП, облаке, безопасности и видеонаблюдении. |
| Калькулятор сделок       | Получить объяснимый предварительный диапазон стоимости и подготовить основу для коммерческого предложения.                 |

Сквозные сценарии, которые должны появиться позднее: авторизация/2FA, уведомления и подписки, экспорт CSV/CRM, формирование коммерческого предложения в DOCX, аудит действий.

## Текущее состояние

Реализован **визуальный прототип фронтенда**, а не готовая бизнес-система.

- Есть базовая архитектура, маршрутизация, глобальная оболочка, тема Ant Design, UI Kit и Storybook.
- Есть визуальные страницы всех трёх модулей с локальными mock-данными.
- Есть физическая модель данных PostgreSQL/PostGIS в документации.
- Нет реального backend API, RTK Query, авторизации, 2FA, реального экспорта, генерации DOCX, расчётной логики, настоящих карт и библиотек графиков.
- Данные в интерфейсе намеренно помечены как «Демонстрационные данные».

## Стек и ограничения

- React 19, TypeScript 6, Vite 6.
- React Router 7.
- Ant Design 6, `@ant-design/icons`, русская локализация.
- Feature-Sliced Design, CSS Modules.
- Redux Toolkit и React Redux; Redux Store подготовлен, но серверные данные в него не дублируются.
- Storybook 8 с адаптером `@storybook/react-vite`.
- ESLint, Prettier, Stylelint.

- `npm run build` запускать только после явного разрешения пользователя.

## Архитектура

Направление зависимостей FSD:

```text
app → pages → widgets → features → entities → shared
```

Реально существуют только слои `app`, `pages` и `shared`. `widgets`, `features`, `entities` пока не созданы намеренно: их нужно добавлять, когда появится самостоятельная ответственность и утверждённые API-контракты.

```text
src/
  app/
    layout/              # AppLayout: верхняя панель и боковая навигация
    providers/           # Router, Redux Provider, ConfigProvider Ant Design
    router/              # маршрутизация
    store/               # Redux Store и typed hooks
    stories/             # композиционные Storybook-шаблоны
    styles/              # глобальные стили, токены, foundation stories
  pages/
    market-radar/        # экран радара + mock-data
    investment-navigator/# экран навигатора + mock-data
    deal-calculator/     # экран калькулятора + mock-data
  shared/
    config/              # routes, antd-theme
    lib/                 # форматтеры денег и процентов
    styles/              # общая компоновка страниц
    ui/                  # универсальный UI Kit
```

### Алиасы

| Алиас         | Путь                          |
| ------------- | ----------------------------- |
| `@app/*`      | `src/app/*`                   |
| `@pages/*`    | `src/pages/*`                 |
| `@widgets/*`  | `src/widgets/*`               |
| `@features/*` | `src/features/*`              |
| `@entities/*` | `src/entities/*`              |
| `@shared/*`   | `src/shared/*`                |
| `@/*`         | `src/*`, технический fallback |

Внутри одного среза допустимы относительные импорты. Между срезами и слоями нужно использовать алиас и только публичный API через `index.ts`.

### Кодовые соглашения

- Общение и документация — на русском языке.
- Комментарии в коде — только на английском и только при необходимости.
- Все функции в `src` и `.storybook` — стрелочные.
- React-компонент завершается `export default` в конце файла.
- Баррель `index.ts` может выдавать именованный внешний API, например `export { default as DataPanel }`.
- Универсальный UI без предметного смысла хранится в `shared/ui`; предметные компоненты не должны попадать туда.
- Локальное состояние оставлять в компоненте; воспроизводимые фильтры в будущем хранить в URL; Redux Toolkit использовать только для общего клиентского состояния.
- После согласования API серверное состояние подключать через RTK Query.

## Навигация и существующий UI Kit

В `AppLayout` реализованы:

- боковое меню трёх бизнес-модулей;
- верхняя панель с заголовком текущей страницы, поиском, уведомлениями и профилем;
- адаптивная замена бокового меню на Drawer.

Существующие универсальные компоненты:

| Компонент    | Назначение                                                                                           |
| ------------ | ---------------------------------------------------------------------------------------------------- |
| `AppShell`   | Каркас приложения: боковая навигация, header, content.                                               |
| `LogoSlot`   | Заменяемый слот для оригинального логотипа пользователя. Не имитирует логотип текстовой графикой.    |
| `PageHeader` | Заголовок раздела, подзаголовок, действия и хлебные крошки.                                          |
| `FilterBar`  | Контейнер для локальных фильтров и сброса условий.                                                   |
| `KpiCard`    | Отображение KPI и тренда; не вычисляет метрики.                                                      |
| `DataPanel`  | Контейнер данных со состояниями loading, empty и error; вариант `analytics` для контрастной области. |

## Визуальная концепция и бренд

Утверждена концепция **«Единое рабочее пространство + Аналитический радар»**:

- светлая B2B-оболочка с постоянной навигацией;
- контрастная поверхность используется только для карт, тепловых слоёв и сложной аналитики;
- карточки, таблицы, фильтры и калькулятор остаются на светлой поверхности;
- пользователь добавит оригинальный логотип самостоятельно.

Подтверждённые брендовые значения:

| Цвет                  | Значение  | Назначение                                                           |
| --------------------- | --------- | -------------------------------------------------------------------- |
| Rostelecom Purple     | `#7700FF` | Главные действия, выбранные состояния, ссылки и ключевые показатели. |
| Rostelecom Orange     | `#FF4F12` | Только приоритетные действия, предупреждения и отдельные акценты.    |
| Rostelecom Light Blue | `#749FD6` | Вторичные информационные акценты и серии графиков.                   |
| Rostelecom Lavender   | `#E8D2ED` | Выбранные фильтры и карточки.                                        |
| Rostelecom Cool Grey  | `#E3E8EC` | Разделители и нейтральные поверхности.                               |

В совместном использовании фирменных акцентов: минимум 70% фиолетового и максимум 30% оранжевого. Каждый дополнительный цвет занимает не более 10% площади макета. Базовый фон — белый или светло-серый.

- реальный пересчёт, сохранение расчёта, валидация, генерация коммерческого предложения.

## Данные и физическая модель

Целевая БД — PostgreSQL с PostGIS. Основные схемы: `auth`, `reference`, `geo`, `market`, `investment`, `pricing`, `notification`, `audit`, `integration`.

Важные связи:

- регион → муниципалитет → организация;
- организация → финансовые показатели и клиентские отношения;
- организация → инвестиционные проекты → объекты, события, тендеры, потребности;
- пользователь → расчёты сделок → позиции, аналоги, коммерческие предложения.

Исходные данные предполагаются из ФНС, ЕИС/госзакупок, кадастра, инвестиционных реестров и поставщиков цен. Внешние источники загружаются через API/ETL; фронтенд не работает с ними напрямую.

## Storybook

Storybook настроен через `.storybook/main.ts` и `.storybook/preview.tsx`, использует тему Ant Design и русскую локализацию.

Существующие разделы историй:

- `Foundations/Brand palette`;
- `Shared/*` для UI Kit;
- `Templates/Workspaces`;
- `Pages/Market radar`;
- `Pages/Investment navigator`;
- `Pages/Deal calculator`.

Для каждого нового универсального компонента добавлять как минимум default-story. Для компонентов с данными добавлять `loading`, `empty`, `error`, если эти состояния применимы. Не менять Storybook без явной задачи пользователя.

## Приоритет следующей разработки

1. Согласовать источник и контракт backend API.
2. Создавать `entities` по одному, начиная с доменной сущности ближайшего реализуемого сценария.
3. Добавить RTK Query и URL-состояние фильтров после согласования контрактов.
4. Реализовать реальную карту и визуализации только после выбора источника геоданных и библиотеки.
5. Реализовать экспорт, подписки, авторизацию/2FA и генерацию КП как самостоятельные features.
