# UI-спецификация бизнес-модулей

Документ определяет, какие блоки необходимо спроектировать для аналитической платформы. Он основан на ТЗ, физической модели данных и утверждённой концепции «Единое рабочее пространство + Аналитический радар».

Все примеры значений в прототипе являются демонстрационными. Реальные данные, формулы, карты и интеграции добавляются только после согласования API и бизнес-правил.

## Сквозной каркас платформы

| Блок                         | Что содержит                                                                                       | Назначение в дизайне                                                                                              |
| ---------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Боковая навигация            | Логотип, «Радар присутствия», «Инвестиционный навигатор», «Калькулятор сделок»                     | Постоянный переход между основными модулями. Активный пункт выделяется фиолетовым текстом на лавандовой подложке. |
| Верхняя глобальная панель    | Название текущего раздела, поиск, уведомления, профиль пользователя                                | Глобальный контекст и действия. Не содержит фильтры конкретной страницы.                                          |
| Заголовок страницы           | Название, поясняющий подзаголовок, хлебные крошки при необходимости, основные и вторичные действия | Показывает цель раздела и его важнейшие действия.                                                                 |
| Локальная область фильтрации | Основные фильтры, число активных условий, «Сбросить», дополнительные условия                       | Управляет только данными открытого модуля. На мобильном устройстве открывается в Drawer.                          |
| Метка актуальности           | Время обновления, источник при необходимости, статус «демонстрационные данные» в прототипе         | Не даёт принять данные за актуальные или реальные.                                                                |
| Рабочие панели               | Карточки с заголовком, тулбаром и контентом                                                        | Унифицированные контейнеры для карт, таблиц, списков, форм и аналитики.                                           |

### Общие правила состояний

Каждый блок, зависящий от данных, проектируется минимум в четырёх состояниях:

| Состояние        | Поведение                                                                                           |
| ---------------- | --------------------------------------------------------------------------------------------------- |
| Загрузка         | Skeleton вместо KPI, списка, карты или таблицы; структура страницы не меняется.                     |
| Успех            | Показ данных, времени обновления и доступных действий.                                              |
| Пустой результат | Понятное объяснение, почему данных нет, и действие «Сбросить фильтры» или изменение условий.        |
| Ошибка           | Ошибка только в затронутой панели, кнопка «Повторить»; остальные доступные блоки остаются видимыми. |

## 1. Радар присутствия

### Цель экрана

Помочь менеджеру найти территории и организации с потенциалом для развития продаж, увидеть текущий клиентский статус и «белые пятна» покрытия.

### Компоновка desktop

```text
PageHeader: название + экспорт CSV + сохранить представление
FilterBar: период / регион / отрасль / выручка / динамика / статус клиента
KPI: 4 карточки
┌───────────────────────────────────────┬──────────────────────────┐
│ Карта возможностей                    │ Приоритетные территории  │
│                                       │                          │
└───────────────────────────────────────┴──────────────────────────┘
Таблица организаций
```

### Блоки для дизайна

| Блок                 | Состав и данные                                                                                                            | Действия и поведение                                                                                                                                   | Статус реализации UI                                                   |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| Заголовок            | «Радар присутствия», короткое описание задачи                                                                              | «Экспорт CSV» — вторичное действие; «Сохранить представление» — primary                                                                                | Есть базовый `PageHeader`; визуальный прототип добавлен.               |
| Фильтры              | Период, регион, отрасль, диапазон выручки, динамика выручки, статус клиента                                                | Выбор нескольких условий, счётчик активных условий, сброс. Дополнительные фильтры скрываются на малой ширине.                                          | Есть `FilterBar`; будущая feature — реальная фильтрация.               |
| KPI                  | Количество организаций, потенциальные клиенты, «белые пятна», средняя динамика выручки                                     | Клик по KPI в будущем может применять преднастроенный фильтр. Оранжевый используется только для одного требующего внимания показателя.                 | Есть `KpiCard`; данные демонстрационные.                               |
| Карта возможностей   | Контрастная аналитическая поверхность, условные точки/тепловые зоны, легенда слоёв, выбранная территория, время обновления | Выбор точки синхронизирует территорию с таблицей и рейтингом. Размер/подпись точки показывает масштаб выборки; смысл не кодируется только цветом.      | Есть SVG/CSS-схема. Настоящая карта и слои требуют отдельного решения. |
| Рейтинг территорий   | Позиция в рейтинге, название территории, количество организаций, потенциал                                                 | Выбор строки выделяет ту же территорию на карте.                                                                                                       | Визуальный список реализован.                                          |
| Таблица организаций  | Организация, ИНН, отрасль, регион, выручка, динамика, клиентский статус, потенциал                                         | Сортировка, серверная пагинация, экспорт, переход в карточку организации. Первые столбцы закреплены, горизонтальная прокрутка находится внутри панели. | Табличный прототип реализован; ИНН и API пока не подключены.           |
| Карточка организации | Реквизиты, динамика финансовых показателей, клиентские отношения, связанные проекты                                        | Открытие по строке таблицы; быстрые действия менеджера определяются отдельно.                                                                          | Будущий entity/widget.                                                 |

### Визуальные приоритеты

- Карта — единственная контрастная тёмная поверхность на странице.
- Фиолетовый обозначает активный слой, выбранную территорию и главное действие.
- Оранжевый используется только для территории или KPI, требующих внимания.
- Голубой подходит для вторичных слоёв или сравнительной серии; лавандовый — для выбранной строки/карточки.

## 2. Инвестиционный навигатор

### Цель экрана

Помочь найти проекты, где требуются цифровая инфраструктура, АСУ ТП, облако, безопасность или видеонаблюдение, и подписаться на изменения по ним.

### Компоновка desktop

```text
PageHeader: название + экспорт + создать подписку
FilterBar: регион / муниципалитет / отрасль / стадия / сроки / потребности / бюджет
KPI: 4 карточки
┌──────────────────────────────┬────────────────────────────────┐
│ Список проектов              │ География проектов             │
│                              │ + легенда / выбранный проект   │
└──────────────────────────────┴────────────────────────────────┘
Табы: События | Тендеры
Таблица выбранной вкладки
```

### Блоки для дизайна

| Блок               | Состав и данные                                                                                               | Действия и поведение                                                                                 | Статус реализации UI                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Заголовок          | «Инвестиционный навигатор», описание поиска проектов                                                          | «Экспорт» — secondary; «Создать подписку» — primary                                                  | Есть базовый и прототипный UI.                                  |
| Фильтры            | Регион, муниципалитет, отрасль, стадия, период реализации, тип потребности, бюджет, сохранённое представление | Условия должны быть воспроизводимы в URL после подключения логики.                                   | Визуальный набор фильтров реализован частично.                  |
| KPI                | Активные проекты, проекты на строительстве, проекты с цифровыми потребностями, плановый объём инвестиций      | Показывают размер рынка, а не заменяют фильтрацию.                                                   | Есть `KpiCard` и mock-данные.                                   |
| Список проектов    | Название, инициатор, регион, стадия, бюджет, сроки, нужные решения, релевантность                             | Выбор карточки синхронизирует географию и открывает детали по действию.                              | Визуальный список реализован.                                   |
| География проектов | Контрастная панель с условными точками, легендой, выбранным проектом и кратким описанием                      | Клик по точке выбирает проект. Для настоящей карты нужен источник геоданных и правила кластеризации. | Реализована схема, не географическая карта.                     |
| Детали проекта     | Стадия, инициатор, объекты, сроки, бюджет, потребности, последние события, статус подписки                    | Открываются в правом Drawer на desktop и на весь экран на mobile.                                    | Drawer-прототип реализован; полное наполнение — будущий widget. |
| События и тендеры  | Вкладки «События» / «Тендеры»; дата, проект, тип, описание, дедлайн, источник, статус                         | Сортировка и переход к источнику. Тендеры не смешиваются с событиями в одной таблице.                | Табличный прототип событий реализован.                          |
| Подписка           | Условия подписки, канал уведомлений, частота, статус                                                          | Создание и изменение требуют отдельной feature и API.                                                | Будущая feature.                                                |

### Визуальные приоритеты

- Список и география равноправны: пользователь может начинать работу с любого из них.
- Стадия проекта всегда дублируется текстом и Tag, а не только цветом.
- Оранжевый допустим для срочных дедлайнов или стадии, требующей внимания; не используется для всех строительных проектов.

## 3. Калькулятор сделок

### Цель экрана

Помочь специалисту зафиксировать параметры потенциальной сделки, увидеть объяснимый ориентировочный диапазон стоимости и подготовить основу для коммерческого предложения.

### Компоновка desktop

```text
PageHeader: название + сохранить черновик + сформировать КП
Steps: Параметры → Состав решения → Расчёт
┌────────────────────────────────────┬────────────────────────────┐
│ Параметры сделки                    │ Предварительная оценка     │
│ Состав решения                      │ Диапазон + факторы         │
│                                    │ Уверенность + CTA          │
└────────────────────────────────────┴────────────────────────────┘
Аналоги расчёта + допущения
```

### Блоки для дизайна

| Блок                     | Состав и данные                                                                             | Действия и поведение                                                                                                                 | Статус реализации UI                                        |
| ------------------------ | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| Заголовок                | «Калькулятор сделок», объяснение назначения                                                 | «Сохранить черновик» — secondary; «Сформировать КП» — primary и недоступно, пока не заполнены обязательные поля и не получен расчёт. | Визуальный прототип реализован.                             |
| Шаги сценария            | «Параметры», «Состав решения», «Расчёт»                                                     | Показывают прогресс, но не заменяют навигацию платформы. У пройденного/текущего/недоступного шага должны быть разные состояния.      | Реализован `Steps`-прототип.                                |
| Параметры сделки         | Тип проекта, отрасль, регион, масштаб, сроки, схема финансирования                          | Обязательные поля, подсказки единиц измерения, inline-валидация и summary ошибок.                                                    | Форма-прототип реализована; реальная валидация отсутствует. |
| Состав решения           | Работы, оборудование, ПО, сервисы; наименование, единица, количество, цена, итог            | Добавление/удаление/редактирование позиции, пересчёт итога. На mobile — карточки вместо широкой таблицы.                             | Демонстрационная таблица реализована.                       |
| Панель результата        | Минимум, наиболее вероятная оценка, максимум, валюта, число аналогов, степень уверенности   | На desktop располагается рядом с формой и остаётся видимой при прокрутке; на tablet/mobile следует за формой.                        | Визуальный диапазон и факторы реализованы.                  |
| Коэффициенты             | Региональный, срочность, уникальность; значение и краткое объяснение влияния                | Пользователь должен видеть, почему диапазон отличается от базовой стоимости. Не показывать формулу без утверждённого бизнес-правила. | Демонстрационные значения реализованы.                      |
| Аналоги                  | Название проекта, отрасль, регион, дата, стоимость, похожесть                               | Переход в карточку аналога при наличии доступа; пояснение, какие параметры сравниваются.                                             | Табличный прототип реализован.                              |
| Допущения и ограничения  | Источник аналогов, применённые допущения, предупреждение о предварительном характере оценки | Всегда видны рядом с результатом или сразу после него.                                                                               | Частично реализовано через информационное сообщение.        |
| Коммерческое предложение | Статус документа, предпросмотр, вариант скачивания/отправки                                 | Создаётся только после успешного расчёта; документ хранится отдельно, в БД — ссылка на него.                                         | Будущая feature.                                            |

### Визуальные приоритеты

- Главный объект внимания — диапазон стоимости и обоснование, а не сама форма.
- Фиолетовый применяется к подтверждённому основному действию и целевой оценке.
- Оранжевый допустим для предупреждения о низкой уверенности или неполных данных.
- Если аналогов нет, не показывается ложная точность: вместо этого — пустое/предупреждающее состояние с предложением изменить параметры.

## Адаптивность

| Ширина      | Поведение                                                                                                                                                                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| От 1200 px  | Боковая навигация, фильтры в строке, KPI в 4 колонки, split-экраны, закреплённый результат калькулятора.                                                                                                                              |
| 768–1199 px | Боковая навигация превращается в Drawer, KPI размещаются 2×2, списки и карты становятся вертикальными, таблицы прокручиваются внутри панелей.                                                                                         |
| До 767 px   | Header содержит меню, название и критичные глобальные действия. Фильтры открываются в Drawer; KPI — одной колонкой; вторичные действия уходят в overflow; ключевые действия «Создать подписку» и «Сформировать КП» остаются доступны. |

## Состав дизайн-макетов

Для каждого модуля необходимо подготовить:

1. Основной desktop-экран с данными.
2. Tablet-вариант с перестроенной двухколоночной областью.
3. Mobile-вариант с Drawer для меню и фильтров.
4. Состояния loading, empty и error для ключевой панели данных.
5. Состояние выбранного объекта: территория в радаре, проект в навигаторе, готовый/неполный расчёт в калькуляторе.
6. Модальные/выдвижные интерфейсы: детали проекта, дополнительные фильтры, сохранённое представление, создание подписки — после утверждения соответствующих сценариев.
